ChatMCP Hub 1.1.5 — integration notes
Prepared 2026-10-09 for the user's existing Windows installation.

This bundle contains Hub integration source and ChatMCP Hub Companion 1.3.5.
The primary workflow sends user-requested tasks through an ordinary ChatGPT
web conversation. The local Hub executes MCP tools; Companion transports
messages through the browser interface. No OpenAI API key, Sign in with
ChatGPT application integration, or Codex/Work provider is required or started
by the version 1.1.5 main launcher. Legacy provider source may remain in the
bundle for reference; the main workflow does not load its credentials.

The bundle does not include Docker Desktop, Node.js, the Cloud Harness
repository, node_modules, user credentials, a ChatGPT subscription, or the
MCP SuperAssistant browser extension itself. ChatGPT usage remains subject
to the signed-in account's ordinary web allowance, available features and
service terms. Pairing credentials connect Companion to this local Hub;
they are not ChatGPT credentials and do not grant extra model quota.

Runtime dependencies installed or reused by Hub:

1. @wonderwhy-er/desktop-commander 0.2.52
   https://github.com/wonderwhy-er/DesktopCommanderMCP
   Runtime: deploy/.generated/desktop-commander-local.
   The upstream package retains its installation and runtime behavior,
   including telemetry/feature-flag checks. The user has accepted that
   behavior for this setup. Hub does not present it as an offline runtime.

2. @srbhptl39/mcp-superassistant-proxy 0.1.8
   https://github.com/srbhptl39/MCP-SuperAssistant
   Runtime: deploy/.generated/browser-proxy-compat.
   Hub loads this package through a compatibility adapter without overwriting
   the installed upstream package source. The proxy package is distinct
   from the MCP SuperAssistant browser extension. Turn that browser extension
   off in the browser used by the primary Hub workflow to avoid duplicate
   execution; it is only needed for the separate legacy manual workflow.

3. @modelcontextprotocol/sdk
   https://github.com/modelcontextprotocol/typescript-sdk
   Resolved from the installed Desktop Commander dependency tree. The exact
   transitive SDK version is determined by the installed package lock.

4. Existing bestagentkits/cloud-harness-mcp deployment
   https://github.com/bestagentkits/cloud-harness-mcp
   Its version, configuration and permissions remain those installed by the
   user. Hub discovers the complete current tool catalog instead of assuming
   a fixed count. Windows Desktop Commander files and Docker Cloud Harness
   clones remain separate workspaces.

All third-party packages and transitive dependencies retain their respective
licenses, notices and terms. npm installs their distributed license files;
consult those files and the upstream repositories before redistribution.
Pinned top-level versions do not pin every transitive dependency on a new
installation. Keep the generated package-lock files to reproduce a working
dependency tree.

Companion 1.3.5 uses Manifest V3 storage/alarms and host permissions for
https://chatgpt.com/* and http://127.0.0.1:3007/*. It stores a local Hub pairing
token in extension storage. It does not read ChatGPT cookies or use an
internal ChatGPT API, and it does not bypass sign-in, approval or quota
requirements. Browser/UI changes can require compatibility updates.

The new browser bridge currently transports text/JSON messages. It does not
automatically attach image, audio or file outputs to ChatGPT. Retaining all
MCP tools in the catalog does not guarantee every output format can be used
fully through the browser bridge.

The retained manual MCP SuperAssistant compatibility flow was checked
against upstream source at:
https://github.com/srbhptl39/MCP-SuperAssistant/tree/c26168ee2c5708a3a65ef5afd88cda1a97c81734
See extension/HUONG-DAN.txt for the current primary setup and the separate
legacy workflow. Do not run their automatic executors together.

OpenAI, ChatGPT, Codex, Docker, Microsoft, VS Code and upstream project names
identify their respective products. This user-specific integration is not
presented as an official product or supported distribution of those projects.
