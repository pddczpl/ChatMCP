SOURCE REVIEW
- PowerShell uses syntax compatible with Windows PowerShell 5.1.
- Single node.exe / npm.cmd paths are resolved, including duplicate PATH entries.
- Version probing does not pass quoted JavaScript through PowerShell node -e.
- Native stderr is tolerated; errors depend on the native exit code.
- Install success marker is only written after npm exits successfully and is
  removed before a repair install starts.
- No ExecutionPolicy changes, force-killed user processes or lab file edits.
- No configuration secrets are embedded in these deliverable files.

LIMITS OF VALIDATION
No Windows PowerShell runtime or access to the user's F: drive was available.
The installer must complete its own MCP probe on that Windows machine before
the new server can be considered connected there. The live package check used
an isolated Linux test installation with npm lifecycle scripts skipped; the
Windows installer uses normal lifecycle scripts for required binary dependencies.
Browser-extension refresh, actual Windows Python commands, GPU operation and
Sensor Fusion tests have not yet been run as part of this setup.

UPSTREAM BEHAVIOR
Desktop Commander configuration is shared per OS user. allowedDirectories
restricts file tools, not arbitrary terminal commands. The official package can
download a Chrome browser for its PDF feature during install/startup. This setup
does not modify the upstream package to suppress that behavior.
