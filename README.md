# DatGold (formerly ChatMCP)

## Introduction

DatGold is a local-first AI coding agent for a single owner on Windows 10/11 x64. Its WinForms and WebView2 desktop application connects to a local Hub and permission-controlled coding tools. You can inspect repositories, edit files, run approved commands, review Git changes, work with multiple projects and Git worktrees, install reviewed skills, and resume recorded conversations and tasks. A model response is not, by itself, proof that a change or test succeeded.

DatGold offers two distinct interaction modes: **Model API**, using a configured model endpoint and its own API credentials, and **ChatGPT Web Companion**, using a separately paired Chrome/Edge extension and an ordinary user-signed-in ChatGPT website session. Web mode is browser-mediated, text-focused and subject to the website's capabilities; it does not provide API credits or identical model/tool semantics. DatGold is local-first, **not fully offline**: configured AI providers, GitHub and authorized research tools may use the network.

## ChatGPT Web Companion: risks and privacy

The ChatGPT Web Companion **automates the consumer ChatGPT page** (chatgpt.com) through a browser extension: it types the Hub's messages into the tab you are signed in to and reads the reply back. It is not an API, and it is not a channel that OpenAI provides, supports or permits; DatGold is not affiliated with OpenAI. Automating that page **may conflict with OpenAI's Terms of Use**, and your ChatGPT account could be warned or suspended. Everything the agent reads for a task and sends through the Companion (your prompt, tool results, file excerpts, command output) goes **into your ChatGPT chat and stays in your ChatGPT history**, under OpenAI's policies. Use the Model API when you need a channel with clear terms or when the workspace holds client material.

To reduce accidental exposure, and only on a best-effort basis, DatGold masks text that is shaped like a secret before it is sent (`[REDACTED:<label>]`), withholds what a tool read from `.env*`, `*.pem`, `*.key`, `id_rsa*` or other protected files when the call or its result names such a file, and offers an optional **Review before send** that holds each tool result for your approval (off by default). These are pattern-based: they miss secrets without a recognisable shape and cannot know what is confidential for a client. Details and limits: [ChatGPT Web Companion privacy](docs/COMPANION-PRIVACY.md).

## Guide

### Install and launch

1. Download the latest **DatGoldSetup.exe** (**ChatMCPSetup.exe** in releases up to v3.10.2), its **.sha256** file, and **RELEASE-MANIFEST.json** from [GitHub Releases](https://github.com/pddczpl/ChatMCP/releases/latest). Verify the published SHA-256 against the actual installer bytes before running it.
2. Use **Windows 10 or 11 x64**, with **Microsoft Edge WebView2 Runtime** and **Git for Windows**. Git is needed for the repository and worktree workflows. The release installer bundles its portable Node.js runtime, supported language servers, Tree-sitter WASM grammars, and embedded Python; these do not need separate installation just to run the packaged app. Microsoft Edge/Chromium itself, an AI account or API key, Git, and WebView2 are not supplied by the installer.
3. Run the installer, launch DatGold, and select or register a project directory using the native workspace picker. The local Hub normally listens on **127.0.0.1:3007**; do not expose it through a public interface or reverse proxy.

### Configure an AI connection

4. In **Settings**, select Model API mode and choose a provider preset or a custom gateway. Check the **protocol** (Gemini generateContent, OpenAI Chat Completions, OpenAI Responses, or Anthropic Messages), **base URL**, optional endpoint path, **model**, authentication mode, and context-window setting independently. Enter an API key or select a supported environment variable; use **Save & Test** to check actual connectivity and tool support. A custom URL or a model name does not guarantee tool-call compatibility. Ollama and LM Studio require a locally running compatible model.
5. For **ChatGPT Web** mode, download the matching **DatGold-Browser-Companion.zip** (**ChatMCP-Browser-Companion.zip** in releases up to v3.10.2; later releases publish the same file under both names) and its checksum from the same release. Extract the ZIP, open chrome://extensions or edge://extensions, enable Developer mode, choose **Load unpacked**, and select the extracted folder containing the extension's manifest.json (not the repository-root legacy manifest). Open a signed-in chatgpt.com tab, generate a fresh pairing code in DatGold Settings, and pair through the Companion popup. Approve browser-extension installation yourself; the desktop installer cannot enable it silently. Re-pair when necessary after reinstalling or changing the extension ID.

### Use, verify, and recover

6. Select the intended workspace and a permission mode: **Read Only**, **Review** (approval before mutations), **Autonomous** (bounded permitted actions), or explicitly authorized **Full Access**. Full Access executes permitted commands with your Windows account privileges, not inside a universal OS sandbox.
7. Start a task with its expected changes and acceptance checks. Watch tool results, approvals, actual Git diffs, worker outcomes, and verification evidence. An agent's final message or a green-looking status does not substitute for fresh test results. Research workflows and coding worktrees have different integration guarantees; review changes before integrating them.
8. Use **Stop** to request cancellation; stopping does not undo changes. Use **Continue** in the same conversation to create a new run and retain historical context. After a crash or an uncertain write, inspect on-disk files and Git state before deciding what to retry; the Hub must not automatically replay ambiguous mutations.
9. To update, finish or stop active work, download and verify the latest installer, and install over the owned installation. The installer may refuse an active task or foreign Hub process. If using an unpacked Browser Companion, update that extension separately, reload the ChatGPT tabs, and re-pair if required. Keep rollback and recovery evidence until the installation is confirmed healthy.
10. For error diagnosis, see [Troubleshooting](docs/TROUBLESHOOTING.md), [Windows setup](docs/WINDOWS-SETUP.md), [Desktop application](docs/DESKTOP-APP.md), [User guide](docs/USER-GUIDE.md), and [development and test instructions](docs/DEVELOPMENT.md). The [documentation library](docs/INDEX.md) links the remaining detailed architecture, security, code-intelligence and historical verification material.

## Security

DatGold is intended for one trusted owner on one Windows account, not public or multi-tenant deployment. The Hub listens on 127.0.0.1 only, and every API request (reads and the live event streams included) must carry a per-launch secret as `Authorization: Bearer`. The Hub publishes that secret in `run/hub-session.json` inside its data folder, a file only your Windows account can read, and makes a new one at every start; the desktop app, the launcher scripts and the installer read it from there, and the dashboard receives it through a one-time sign-in link. Host, Origin and CSRF checks remain on top of it. This boundary protects against other Windows accounts, sandboxed processes that cannot read your files, and web pages in your browser. It does **not** protect against malware or any other program running as you: such a program can read the same file the desktop app reads. The paired Browser Companion uses separate authorization (its two read-only status routes answer any request that presents a browser-extension origin without the secret, so a local program can read the workspace path and version that way). The [threat model](docs/THREAT-MODEL.md) lists these and the other residual risks. Treat code, skills, tool output, and model output as untrusted. Use Review for sensitive projects, inspect approvals, and understand that **Full Access** gives tools the effective access of your Windows account.

Model API requests can send task instructions, workspace excerpts, tool schemas/results, and user-selected attachments to the **configured provider**. The application uses local credential protections, but users must still protect prompts, logs and exported diagnostics. Git worktrees provide checkout separation, **not operating-system isolation**; host commands and supported Windows Sandbox verification provide different assurance levels.

DatGold can tell you when a newer release exists (Settings → Updates) and, when you click **Download**, fetch its installer. It looks only after you say yes to a question the app shows once, and **Check now** works at any time; until you answer, the app makes no request of its own to look for a new release. When it looks, it requests `RELEASE-MANIFEST.json` of the newest stable release from github.com, which hands the request on to GitHub's file server (release-assets.githubusercontent.com), and then the signature file of that release, `RELEASE-MANIFEST.json.sig`: two short chains of GET requests, about every 12 hours while it runs. Those servers see your IP address and the line `DatGold/<version>`, nothing else about you. The signature is an ECDSA P-256 signature over the exact bytes of the manifest, and the app offers **Download** only for a release whose signature checks against a public key that ships with the app (a release that is not signed, or whose signature does not check, is announced without a button). A download starts only when you click **Download**, never by itself and never after a check; the installer is streamed to a folder of the Hub's own and kept only if its size and SHA-256 are the ones in the signed manifest. In the desktop app, a downloaded installer can be installed from the page: **Install and restart** closes the app, runs the installer and opens the new version (it is held back with its reason while tasks run, and a plain browser is only told where to do it). Nothing is installed or run until you click **Install and restart**: the app first checks the downloaded file and its signature again with its own code, against the public keys built into the program, and refuses to run anything that does not match the signed manifest. The installer replaces the files in one transaction that is rolled back on an error and opens the right app again, and the next start of the app tells you **Updated to DatGold x.y.z**, or why the update did not go through and which version still runs (the installer leaves that note only when no program listens on port 3007, which the app uses: a refusal that stopped nothing, for instance because a task is running, is told in the update window and leaves no note for a Hub that may start days later). If an update stops halfway and the old files cannot all be put back, the setup puts them back itself from the backup that stays in the DatGold folder: once (3 seconds after that update failed, while its setup is still running), and again whenever you press **Repair now** in the update window or run the setup again, which offers it. Until the installation is repaired DatGold does not start (its launcher says what to run) and a Hub that you start by hand leaves the note of that update unread. If the backup is damaged or a file was changed by something else, the repair refuses and changes nothing, and the section Recovering an installation by hand of docs/WINDOWS-SETUP.md says what can still be done (it checks every backup first, so it stops, changing nothing, when one is damaged). The installer has no Authenticode signature, and you can still download an installer yourself and compare its SHA-256, as described above. No release carries a signature until the project's owner has made the release key and signed one; the click path in the desktop app has not been tried on a real machine with a real signed release. The [threat model](docs/THREAT-MODEL.md) lists what this can and cannot do.

Check each release's SHA-256 files and **RELEASE-MANIFEST.json** and independently inspect Authenticode signatures where present; checksums alone do not prove publisher identity. See the [Security Policy](SECURITY.md) for limitations, historical disclosures and vulnerability reporting instructions.
